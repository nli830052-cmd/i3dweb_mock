## 0. 현재 "AI 적용" 수준 진단

지금 시스템에 **실제 AI 요소가 들어가 있음** — "가짜 AI"가 아니라 실제 파이프라인이 작동.

| 구성 | AI 여부 | 설명 |
|---|---|---|
| bge-m3 임베딩 + 벡터 검색 | ✅ AI | 의미 기반 검색(ML 임베딩) |
| Qwen3 LLM (의도→action JSON, 답변 생성) | ✅ AI | 생성형 LLM |
| RAG (검색 → LLM 종합) | ✅ AI | 대표적 AI 아키텍처 |
| 규칙기반 키워드 분류(빠른 경로) | ❌ | 단순 매칭 |
| Mock Viewer / SQLite / 액션 실행 | ❌ | 목업·정형 데이터 |

> 결론: **임베딩 의미검색 + LLM + RAG**가 동작하므로 "AI 챗봇 연동"은 정당한 표현.
> 단, 상당 부분은 규칙·목업 골격이고 AI 품질은 로컬 8B 한계 → 현재는 **"AI를 적용한 프로토타입"** 수준.

## 우선순위 추천

1. **멀티턴 대화 맥락** — "단발 질의응답 → 대화형 어시스턴트"로 체감이 가장 크게 상승. 데모 임팩트 최고.
2. **정비 완료 자동 리포트** — 매뉴얼 데이터와 바로 연결되는 실무 가치.
3. **Claude API 옵션** — 현재 로컬 8B 오분류 문제를 근본적으로 완화 (난이도 낮음).
4. (현장형 데모) **음성 입력** 또는 **비전(설비 사진 질의)**.

> 참고: 모든 기능은 현 구조(규칙 빠른경로 + LLM plan + RAG, 백엔드 단일 LLM 호출 지점)를 그대로 활용해 확장 가능.
> LLM 교체/추가는 `backend/rag_server.py`의 호출 지점 한 곳만 손대면 됨.
