## 0. 관점 전환: 챗봇 → AI 어시스턴트

지금까지는 사실상 **"반응형 질의응답 챗봇"** 이에요 (사용자가 물으면 답함).
**AI 어시스턴트**라면 다음 3가지가 더 있어야 해요:

| 축 | 챗봇 (현재) | AI 어시스턴트 (목표) |
|---|---|---|
| **상황 인지** | "이 밸브"를 currentTag로만 앎 | 보고 있는 설비·작업단계·위치·센서까지 맥락으로 |
| **능동성** | 물어야 답함 (수동) | **먼저** 경고·제안·다음 단계 안내 |
| **작업 동반** | 단발 답변 | 작업 시작~점검~기록~보고까지 **동행·대행** |

→ 즉 "물으면 답하는 것"에서 **"옆에서 같이 일하는 동료"** 로 끌어올리는 게 핵심.

### 현재 AI 적용 수준 (진단)
| 구성 | AI 여부 |
|---|---|
| bge-m3 임베딩 + 벡터검색 / Qwen3 LLM / RAG | ✅ 실제 AI |
| 규칙 키워드 분류 / Mock Viewer / SQLite | ❌ 규칙·목업 |

> AI는 진짜로 들어가 있음(임베딩+LLM+RAG). 다만 **반응형 + 8B 한계**라 "AI 적용 프로토타입" 단계.

## A. 상황 인지 (Context-Aware) — 어시스턴트의 기본
| 기능 | 가치 | 난이도 | 설명 |
|---|---|---|---|
| **멀티턴 대화 맥락** | ★★★ | 중 | "거기 안전대는?", "그럼 다음은?" 후속/대명사 이해 |
| **현재 화면 상태를 맥락에 주입** | ★★★ | 중 | 선택 설비·시점·필터·작업단계·위치를 매 질문에 자동 반영 → "이거/여기/지금" 정확 해석 |
| 작업자/세션 메모리 | ★★ | 중 | 진행 중 작업·선호를 세션 넘어 기억, 미완료 작업 이어하기 |

## B. 능동적 지원 (Proactive) — "먼저" 돕는다 ⭐핵심
| 기능 | 가치 | 난이도 | 설명 |
|---|---|---|---|
| **안전 자동 경고** | ★★★ | 중 | 고소작업(2m↑)·추락위험·개구부 설비에 접근/선택 시 **묻기 전에** 경고 + 안전조치 안내 |
| **정비 주기 임박/초과 알림** | ★★★ | 중 | 화면에 들어온 설비 중 주기 초과·Open Point 있는 것 자동 표시 |
| **작업 단계 자동 코칭** | ★★★ | 중 | 현재 단계에 맞춰 다음 단계·체크리스트·주의사항을 **먼저** 제시 |
| **이상감지 연동 경고** | ★★ | 중 | (실제 챗봇에 sensor/anomaly 라우터 존재) 센서 이상 시 경고 + 해당 설비 하이라이트 |

## C. 작업 동반·자동화 (Agentic) — 대신 실행 ⭐핵심
| 기능 | 가치 | 난이도 | 설명 |
|---|---|---|---|

## 우선순위 추천 (AI 어시스턴트화 순서)

1. **상황 인지 강화 (멀티턴 + 현재 화면 맥락 주입)** — 어시스턴트의 토대. "이거/여기/지금"을 정확히 알아야 나머지가 산다.
2. **능동적 지원 (안전 경고 / 주기 알림 / 단계 코칭)** — "먼저 돕는다"가 챗봇과 어시스턴트를 가르는 결정적 차이.
3. **작업 동반 (복합 명령 + 정비 자동 리포트)** — 단발 답변을 넘어 작업을 대행·완결.
4. **멀티모달 (음성/비전)** — 현장 실사용성.
5. **Claude API 옵션** — 위 전부의 품질을 한 번에 끌어올리는 저비용 레버.

> 한 줄 요약: **"물으면 답하는 챗봇" → "보고 있는 상황을 알고, 먼저 경고하고, 작업을 대신 해주는 어시스턴트"** 로 가는 게 방향.
> 모든 기능은 현 구조(규칙 빠른경로 + LLM plan + RAG)를 그대로 확장 가능하며, LLM 교체/추가는 `backend/rag_server.py` 호출 지점 한 곳만 손대면 됨.
