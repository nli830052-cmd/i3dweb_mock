# 채팅 동작 순서 & 파이썬 서버 연동 가이드 (솔루션팀용)

기존 사이트에 챗봇을 얹어 테스트하려는 솔루션팀을 위해, **전송 버튼 클릭 → 최종 응답**까지의
코드 흐름과 파이썬 RAG 서버 연동/배포 관련 사항을 정리한 문서입니다.

---

## 1. 채팅 동작 순서 (버튼 → 응답)

```
sendBtn 클릭  (src/ui/app.js:400)
   └─ onSend()                              src/ui/app.js:27     ← 진입점
        └─ AiBackend.requestAiResponse(req) src/ui/app.js:44     ← 응답 객체(res) 생성
                 │   (실제 본체는 classifier.js:355)
        └─ handleResponse(res)              src/ui/app.js:96→101
                 ├─ renderChat(res)          화면에 답변 출력
                 └─ runActions(res)          3D 뷰어 동작 실행 (ACTION일 때)
```

- 전송 버튼 id: **`sendBtn`** / Enter 키도 동일하게 `onSend()` 호출 (app.js:401)
- `onSend()`은 **호출만** 하고, **응답 JSON을 실제로 만드는 본체는 `src/ai/classifier.js`의
  `requestAiResponse()` (classifier.js:355)** 입니다. ← "최종적으로 응답을 내려주는 코드" 위치

### 응답을 만드는 두 갈래

`requestAiResponse()`는 질문 종류에 따라 응답 출처가 갈립니다 (classifier.js:355~398):

| 순서 | 조건                               | 응답 생성 위치                                               | 파이썬 서버    |
| ---- | ---------------------------------- | ------------------------------------------------------------ | -------------- |
| 1    | 에러 시뮬레이션                    | 예외 throw                                                   | 불필요         |
| 2    | 근거형 질의(이력/주기/공간/매뉴얼) | `RagClient.chat()` → **`POST /api/ai/chat`**      | **필요** |
| 3    | 매뉴얼/절차 질의                   | `RagClient.answer()` → **`POST /api/rag/answer`** | **필요** |
| 4    | 규칙 매칭                          | `classifyRuleBased()` (브라우저 내부)                      | 불필요         |
| 5    | 규칙 미매칭 폴백                   | `RagClient.plan()` → **`POST /api/ai/plan`**      | **필요** |

즉, **응답을 내려주는 코드는 두 군데**입니다.

- **브라우저 mock 응답**: `classifier.js`의 `classifyRuleBased()`, `mkAnswer()` 등 (서버 없이 동작)
- **실제 AI 응답**: `backend/rag_server.py`의 `do_POST()` (rag_server.py:916),
  특히 `/api/ai/chat` 핸들러(rag_server.py:935)

> 💡 파이썬 서버가 꺼져 있으면 `requestAiResponse()`가 `try/catch`로 조용히 4번(규칙기반)으로
> 폴백합니다(classifier.js:367·376·396). 그래서 **서버 없이도 채팅 UI 자체는 동작**하고,
> 근거형·매뉴얼 답변만 mock으로 떨어집니다.

## 2. 파이썬 서버 (localhost:8090) — 운영 주소 vs 내장

- 호출 주소는 **한 곳에 하드코딩**되어 있습니다:
  `src/ai/ragClient.js:14` → `const BASE = "http://localhost:8090";`
  운영의 오픈 주소로 바꾸려면 **이 한 줄만** 수정하면 됩니다. (추후 환경변수 분리 권장)
- 이 서버는 단순 API가 아니라 **임베딩 모델(bge-m3) + 로컬 LLM(Ollama, qwen3.5:9b)** 을
  띄워서 돌립니다. 모델/메모리(가능하면 GPU) 자원이 필요해 **솔루션팀 웹서버에 그대로
  내장하기엔 무겁습니다.**
- 권장 구성: **AI팀이 이 파이썬 서버를 별도 호스트로 띄우고, 솔루션팀은 그 주소(BASE)만 호출.**
  내장 여부는 자원·배포 정책 결정 사항이라 AI팀과 협의가 필요합니다.

## 3. git에서 받으면 되는지 / 별도 파일

- 서버·스크립트 코드는 git에 있습니다:
  `backend/rag_server.py`, `scripts/{ingest_manuals,embed_chunks,search_manuals,build_db}.py`
- 매뉴얼 원본(PDF·MD)도 git에 있습니다: `유지보수메뉴얼/`
- ⚠️ **그런데 코드만으로는 서버가 안 뜹니다.** RAG 인덱스·DB(`data/`)는
  **`.gitignore`로 제외**되어 있어 git에 없습니다. → `backend/README.md`의 빌드 절차로
  **직접 생성**해야 합니다. (매뉴얼 원본이 git에 있으니 재생성은 가능)

| 필요한 것              | git 포함 | 준비 방법                                   |
| ---------------------- | -------- | ------------------------------------------- |
| 서버/스크립트 코드     | ✅       | git pull                                    |
| 매뉴얼 원본(PDF·MD)   | ✅       | git pull                                    |
| 인덱스·DB(`data/*`) | ❌       | `scripts/*` 실행으로 생성 (README 3번)    |
| 파이썬 패키지          | ❌       | `pip install -r backend/requirements.txt` |
| LLM 런타임/모델        | ❌       | Ollama 설치 +`ollama pull qwen3.5:9b`     |

## 4. 정리 — 누가 무엇을 할지

이번 막힘은 사실 **AI팀이 넘겨줄 산출물(실행 매뉴얼·의존성 목록·데이터 생성 절차)이
빠져 있어서**였고, 이번에 아래를 추가했습니다.

- ✅ `backend/requirements.txt` — 코드에서 역추출한 파이썬 의존성
- ✅ `backend/README.md` — 서버 설치·데이터 빌드·실행 매뉴얼 초안
- ✅ `docs/채팅동작_솔루션팀_연동가이드.md` — (이 문서)

**남은 협의/결정 사항(AI팀 ↔ 솔루션팀):**

1. 운영 배포 주소 확정 → `ragClient.js:14` `BASE` 반영 방식 (하드코딩 → 설정/환경변수 권장)
2. 파이썬 서버 호스팅 위치(AI팀 별도 서버 vs 내장) 및 자원(GPU 여부)
3. `data/` 산출물 전달 방식(AI팀이 빌드해 전달 vs 솔루션팀이 스크립트로 생성)
4. Ollama/`qwen3.5:9b` 가동 환경

> 참고 문서: 파일별 역할·담당 구분은 `docs/전체디렉토리role구분.md` 에 정리되어 있습니다.
