# 채팅 동작 순서 & 파이썬 서버 연동 가이드 (솔루션팀용)

기존 사이트에 챗봇을 얹어 테스트하려는 솔루션팀을 위해, **전송 버튼 클릭 → 최종 응답**까지의
코드 흐름과 파이썬 RAG 서버 연동/배포 관련 사항을 정리한 문서입니다.

---

## 1. 채팅 동작 순서 (버튼 → 응답)

```
sendBtn 클릭  (src/ui/app.js:400)
   └─ onSend()                              src/ui/app.js:27     ← 진입점
        └─ AiBackend.requestAiResponse(req) src/ui/app.js:44     ← 응답 객체(res) 생성
                 │   (실제 본체는 classifier.js:355)
        └─ handleResponse(res)              src/ui/app.js:96→101
                 ├─ renderChat(res)          화면에 답변 출력
                 └─ runActions(res)          3D 뷰어 동작 실행 (ACTION일 때)
```

- 전송 버튼 id: **`sendBtn`** / Enter 키도 동일하게 `onSend()` 호출 (app.js:401)
- `onSend()`은 **호출만** 하고, **응답 JSON을 실제로 만드는 본체는 `src/ai/classifier.js`의
  `requestAiResponse()` (classifier.js:355)** 입니다. ← "최종적으로 응답을 내려주는 코드" 위치

### 응답을 만드는 두 갈래

`requestAiResponse()`는 질문 종류에 따라 응답 출처가 갈립니다 (classifier.js:355~398):

| 순서 | 조건                               | 응답 생성 위치                                               | 파이썬 서버    |
| ---- | ---------------------------------- | ------------------------------------------------------------ | -------------- |
| 1    | 에러 시뮬레이션                    | 예외 throw                                                   | 불필요         |
| 2    | 근거형 질의(이력/주기/공간/매뉴얼) | `RagClient.chat()` → **`POST /api/ai/chat`**      | **필요** |
| 3    | 매뉴얼/절차 질의                   | `RagClient.answer()` → **`POST /api/rag/answer`** | **필요** |
| 4    | 규칙 매칭                          | `classifyRuleBased()` (브라우저 내부)                      | 불필요         |
| 5    | 규칙 미매칭 폴백                   | `RagClient.plan()` → **`POST /api/ai/plan`**      | **필요** |

즉, **응답을 내려주는 코드는 두 군데**입니다.

- **브라우저 mock 응답**: `classifier.js`의 `classifyRuleBased()`, `mkAnswer()` 등 (서버 없이 동작)
- **실제 AI 응답**: `backend/rag_server.py`의 `do_POST()` (rag_server.py:916),
  특히 `/api/ai/chat` 핸들러(rag_server.py:935)

> 💡 파이썬 서버가 꺼져 있으면 `requestAiResponse()`가 `try/catch`로 조용히 4번(규칙기반)으로
> 폴백합니다(classifier.js:367·376·396). 그래서 **서버 없이도 채팅 UI 자체는 동작**하고,
> 근거형·매뉴얼 답변만 mock으로 떨어집니다.

## 2. 파이썬 서버 접속 방식 (AI팀 오픈 주소 사용)

- **AI팀 전용 서버(데스크톱) 호스팅 확정**: 
  이 서버는 임베딩 모델(bge-m3) + 로컬 LLM(Ollama, qwen3.5:9b)을 구동하기 위해 높은 자원이 요구됩니다. 따라서 **솔루션팀 웹서버에 내장하지 않고, AI팀 데스크톱 서버(IP: `192.168.0.210`)를 오픈 주소로 띄워 제공**하기로 결정되었습니다.
- 프론트엔드의 호출 주소는 **`src/ai/ragClient.js:14`** 에 이미 반영 완료되었습니다.
  `const BASE = window.AI_SERVER_BASE_URL || "http://192.168.0.210:8090";`

## 3. 솔루션팀 진행 액션 (그냥 받아서 쓰면 됩니다)

AI팀에서 서버를 구동하고 주소를 열어두었으므로, **솔루션팀은 별도의 파이썬 환경 세팅, 데이터 인덱스 빌드, Ollama 설치 등을 할 필요가 전혀 없습니다.**

1. **최신 코드 받기**: `git pull`을 통해 최신 `src/ai/ragClient.js` 코드를 업데이트합니다.
2. **테스트 진행**: 프론트엔드 환경만 띄운 뒤, 채팅창에서 전송 버튼(`sendBtn`)을 눌러 AI 답변이 정상적으로 오는지 확인합니다.
3. *(참고)* 만약 네트워크 접속 오류가 난다면:
   - 두 PC(솔루션팀 테스트 PC와 AI팀 서버)가 같은 사내망에 있는지 확인해주세요.
   - AI팀 담당자에게 파이썬 서버가 켜져 있는지, 방화벽(8090 포트)이 열려 있는지 확인을 요청해주세요.
