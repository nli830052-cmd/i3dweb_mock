## 1. 동작 구조 (LLM-first)

사용자 입력을 **규칙(키워드 필터)이 아니라 LLM이 먼저 해석**한다.
정해진 단어가 없어도 뜻만 통하면 의도를 인식한다. (예: "펌프들 좀 치워봐" → 숨김)

```
사용자 입력
   │
   ▼
[LLM plan] 문장 해석 → 액션 JSON 생성          ← OpenAI API (gpt-4o-mini)
   │
   ├─ 뷰어 조작이면 ──→ 액션 실행 (i3DWEB Viewer SDK)
   ├─ 질문이면 ───────→ [통합 챗] DB/RAG 사실 조회 + LLM 답변 종합
   └─ 서버/API 오류면 → 기존 규칙 필터로 자동 폴백 (오프라인 데모 가능)
```

- **사실(날짜·수치·판정)은 전부 DB/매뉴얼에서만** 나온다. LLM은 ①의도 해석 ②문장 종합만 담당 → 환각(그럴듯한 거짓 답변) 방지.
- 세션 대화 이력을 서버가 최근 6턴까지 기억 → "그거 단면 보여줘" 같은 대명사 해석 가능.

### 설정 방법

| 항목 | 방법 |
|---|---|
| API 키 | repo 루트 `.env` 파일에 `OPENAI_API_KEY=sk-...` (git에 안 올라감) |
| 모델 변경 | `.env`에 `OPENAI_MODEL=gpt-4o` (기본: gpt-4o-mini) |
| 서버 실행 | `python backend/rag_server.py` (http://localhost:8090) |
| 키 없이 실행 | 자동으로 로컬 Ollama(qwen3.5:9b) 폴백 — 폐쇄망/오프라인용 |
| 모드 확인 | `GET /api/ai/config` → `{"llmFirst": true, "engine": "OpenAI API", ...}` |

키를 바꾸면 **서버 재시작 + 브라우저 새로고침** 필요 (프런트가 로드 시 모드를 감지함).

### 액션 JSON 규약 (솔루션팀 협의 확정)

- 형식: `"actions": [{ "params": {}, "type": "...", "targetType": "...", "targetValue": "..." }]`
- **켜기/끄기(ON/OFF)는 `params.on: true/false`** (CLIP / PID / MONITORING / AVATAR / KEY_MAP)
- 문장에 태그가 없으면 **현재 선택 태그**를 `targetValue`에 자동 주입
- 현재 선택 태그도 없으면 태그를 지어내지 않고 SEARCH 또는 비움

### 3-4. 매뉴얼 검색 (RAG — 벡터검색 + LLM 종합)

"절차 / 방법 / 기준"을 묻는 일반 지식 질문. 답변에 근거 매뉴얼 발췌(접이식)가 붙는다.

- "그랜드패킹 교체 절차 알려줘"

- "시트 누설 시 조치 방법 알려줘"
- "특별점검 착수 기준이 뭐야?"
- "예비품 목록 알려줘"

### 3-5. 박람회 데모 기능 (2026-07-14 추가)

| 기능 | 사용법 | 동작 |
|---|---|---|
| **오늘 점검 브리핑** (에이전트) | 챗에 **"오늘 점검할 거 알려줘" / "오늘 뭐 해야 돼?" / "오늘 점검할 구역 알려줘"** 등 자유 입력 | AI가 DB 실수치로 5단계 브리핑: 짧은 내레이션(타이핑) + **구조화 표(kv)·안전조치 리스트·작업 단계 진행바**를 함께 출력하면서 뷰어를 **스스로 조작**(이동→단면→작업구역). 내레이션은 매번 LLM이 새로 다듬고, 수치가 담긴 표는 DB값 그대로(왜곡 방지) |
| **사진 진단** (Vision) | 입력창의 첨부/카메라 버튼으로 현장 사진 업로드 (질문을 입력창에 쓴 채 올리면 함께 반영) | Vision LLM이 설비/부위/이상징후/심각도(정상·주의·위험) 판독 → 판독 결과로 매뉴얼 자동 검색 → 진단+조치 근거를 리치 카드로. OpenAI 연결 시에만 동작 |
| **생각 과정 표시** | 자동 | 응답 대기 중 "의도 분석 → 매뉴얼·CMMS 조회 → 답변 작성" 단계가 실시간 표시 |
| **타이핑 효과** | 자동 | 답변이 한 글자씩 출력된 뒤 표/서식으로 전환, 이어서 권고·근거 표시 |

### 3-6. 데모 시나리오 — 예상 질문 리스트 (복합형)

> 실제 사용자는 "이동해줘" 같은 단순 명령보다 **질문+행동이 섞인 문장**을 쓴다.
> LLM이 답변(QUERY/RAG)과 뷰어 액션을 한 번에 생성(ANSWER_WITH_ACTION)하므로 아래처럼 물으면 된다.
> ✔ = 실제 테스트로 확인된 문장.

**A. 작업 시작 (에이전트 브리핑)**
- ✔ "오늘 점검할 거 알려줘" / "오늘 뭐 해야 돼?" / "오늘 점검할 구역 알려줘" / "오늘 점검 대상 어디야?"
  → 5단계 브리핑 (상태 요약 표 + 이동→단면→작업구역 자동 시연)

**B. 설비 상태 파악 (답변 + 카메라)**
- ✔ "GV-101A 정비 이력 알려주고 위치도 보여줘" → 이력 카드 + 카메라 이동
- "이 밸브 마지막으로 언제 정비했어?" → 이력 답변 (선택 태그 기준)
- "정비 주기 지났는지 확인해줘" → 주기 판정 카드 (초과 일수 계산)
- "미조치 사항 남은 거 있어?" → Open Point 표

**C. 작업 준비 (안전 + 공간)**
- ✔ "이 밸브 작업 공간 충분한지 구역 표시하면서 알려줘" → 공간 판정 + 작업 구역 표시
- "여기 고소작업에 해당돼? 작업발판 필요해?" → 높이 판정 + 안전조치 안내
- "주변에 추락 위험이나 개구부 있어?" → 위험 요소 답변
- "비상구까지 경로 보여줘" → 경로 표시

**D. 정비 실행 (매뉴얼 + 뷰어)**
- "그랜드패킹 교체 절차 알려줘" → 매뉴얼 RAG (발췌 근거 첨부)
- "단면 열어서 안쪽 보여줘. 우선 점검할 부품이 뭐야?" → 단면 + 우선 부품 답변
- "이 밸브 연계 도면 띄워줘" → P&ID 표시
- "지금 어디 단계까지 했지? 체크리스트 보여줘" → 단계 진행바 + 체크리스트 표

**E. 현장 대응 (사진 / 모니터링)**
- ✔ (사진 업로드) + "이거 왜 이래?" → Vision 진단 + 매뉴얼 조치 절차
- "이 밸브 실시간 상태 보여줘" → 모니터링 화면
- "시트에서 누설되면 어떻게 조치해?" → 매뉴얼 부위별 조치 기준

**F. 연속 대화 (멀티턴)**
- "GV-101A로 가줘" → "그거 단면 보여줘" → "누설 이력 있어?" → "이제 다 원래대로 해줘"

## 4. 알려진 제약 / 협의 필요 사항

1. **응답 지연**: 메시지당 약 4~6초 (질문형은 LLM 2회 호출: 의도 분류 + 답변 종합). 단축 필요 시 분류·종합 통합 최적화 가능.
2. **타입 단위 숨김 (솔루션팀 협의 필요)**: 스펙상 `HIDE`/`SHOW_ONLY`는 태그 단위인데, 사용자는 "펌프 다 숨겨줘"처럼 타입 단위로 말하는 경우가 많음. 현재 AI는 `targetType:"TYPE", targetValue:"PUMP"`도 생성함 → 실제 뷰어가 타입 숨김을 지원할지, AI가 태그 목록으로 풀어 보낼지 결정 필요.
