# 사용자 입력 → 라우팅(질문 분류) 정리

> 챗봇이 사용자의 자연어 한 줄을 받아 **어떤 데이터 소스(뷰어 조작 / CMMS DB / 작업오더 / 매뉴얼 RAG)** 로 보내는지를 정리한 문서.
> 핵심 코드: `src/ai/classifier.js`(프런트 규칙기반), `backend/rag_server.py`(LLM+RAG 백엔드).

---

## 0. 한눈에 보기

```
사용자 입력
   │
   ▼
[classifier.js] requestAiResponse()         ← 프런트 진입점
   │
   ├─ ① isGroundedQuery() ?  ──► (예) 백엔드 통합챗 /api/ai/chat  (LLM+RAG+DB 5단 답변)
   │
   ├─ ② isManualQuery() ?    ──► (예) 백엔드 RAG /api/rag/answer  (매뉴얼 벡터검색)
   │
   ├─ ③ classifyRuleBased()  ──► 규칙 매칭되면 즉시 반환 (뷰어 조작 등)
   │
   └─ ④ 규칙 미스(_fallback) ──► 백엔드 make_plan (LLM이 action JSON 직접 생성)
```

* **분류가 먼저, 데이터 조회는 나중**입니다. 질문을 카테고리로 나눈 뒤 그에 맞는 소스로 보냅니다.
* 같은 질문이라도 **어느 카테고리로 분류되느냐**에 따라 매뉴얼 검색을 탈 수도, 작업오더 mock 조회를 탈 수도 있습니다. (← 오분류 사고의 원인 지점)

## 1. 프런트 진입점 — `requestAiResponse()`  (`classifier.js:365`)

호출 순서대로 4단계. 위에서 매칭되면 **그 자리에서 반환**하고 아래로 안 갑니다.

| 순서 | 판별 함수                                 | 참이면 보내는 곳                  | 비고                                                         |
| ---- | ----------------------------------------- | --------------------------------- | ------------------------------------------------------------ |
| ①   | `isGroundedQuery()` `:357`            | 백엔드 통합챗`RagClient.chat()` | 근거형(이력·주기·공간·단계·매뉴얼) 질의 → 5단 구조 답변 |
| ②   | `isManualQuery()` `:459`              | 백엔드 RAG`RagClient.answer()`  | 매뉴얼/절차 질의 → 벡터검색 + LLM 종합                      |
| ③   | `classifyRuleBased()` `:39`           | 규칙 매칭 결과                    | 뷰어 조작·검색·이동 등 (아래 2장)                          |
| ④   | `RagClient.plan()` → `executePlan()` | LLM이 만든 action JSON 실행       | 규칙이 못 잡은 자유 입력                                     |

`isGroundedQuery = isManualQuery ∨ isWorkConditionQuery ∨ isStageQuery ∨ isCycleQuery ∨ isMaintenanceQuery`

> ⚠️ ①에서 `isStageQuery`가 참이면 곧장 통합챗/작업오더 경로로 갑니다. **"체크리스트" 같은 단어가 여기서 매뉴얼이 아닌 작업단계로 새는 지점.**

## 2. 규칙기반 분류 — `classifyRuleBased()` 우선순위 (`classifier.js:39`)

위에서부터 순서대로 검사하며, **먼저 매칭되는 규칙이 이김**(precedence).

| #  | 조건 키워드                                                                                | 결과 액션                                                | responseType     |
| -- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------- | ---------------- |
| 1  | 숨겨/숨김/안보이게/꺼줘/가려 (단 "다시" 제외)                                              | `HIDE_OBJECT`                                          | ACTION           |
| 2  | 다시 보여/다시 표시/켜줘                                                                   | `SHOW_OBJECT`                                          | ACTION           |
| 3  | "계통" + (만/위주/따로)                                                                    | `ISOLATE_SYSTEM`                                       | ACTION           |
| 4  | 타입 + (만 보여/만 표시…)                                                                 | `FILTER_BY_TYPE`                                       | ACTION           |
| 5  | 뒷면/후면/측면/돌려/회전                                                                   | `ROTATE_VIEW`                                          | ACTION           |
| 6  | 찾아/검색 + (태그 없음)                                                                    | `SEARCH_EQUIPMENT`                                     | ACTION           |
| 7  | 정비 구역 표시                                                                             | `SHOW_WORK_ZONE`                                       | ACTION           |
| 8  | 작업공간/간섭/사다리/발판/고소작업/추락/개구부                                             | `buildWorkConditionAnswer` (spatial)                   | ANSWER(grounded) |
| 9  | "점검" + (순서/동선/루트)                                                                  | `SHOW_INSPECTION_ROUTE`                                | ACTION           |
| 10 | 가까운 + (점검/대상)                                                                       | `FIND_NEAREST`                                         | ACTION           |
| 11 | (점검자/작업자) + 위치                                                                     | `SHOW_WORKER_POSITION`                                 | ACTION           |
| 12 | 점검 + 위치 + (이동/안내/가줘…)                                                           | `MOVE_TO_INSPECTION`                                   | ACTION           |
| 13 | 경로 / (비상 + 탈출·출구·대피)                                                           | `SHOW_PATH`                                            | ACTION           |
| 14 | **`isStageQuery`** (단계/체크리스트/다음작업/준비사항/점검사항/누락/미완료/완료안) | `buildStageAnswer` (작업오더)                          | ANSWER           |
| 15 | `isCycleQuery` (주기/예정일/다음정비/부품, 교체+판단)                                    | `buildCycleAnswer` (CMMS)                              | ANSWER           |
| 16 | `isMaintenanceQuery` (이력/분해정비/가스켓/누설/반복/점검결과/오픈포인트)                | `buildMaintenanceAnswer` (CMMS)                        | ANSWER           |
| 17 | 이동/가줘/안내/위치/보여/데려 (+태그)                                                      | `JUMP_TO`                                              | ACTION           |
| 18 | 그 외                                                                                      | `mkAnswer` (`_fallback=true`) → 백엔드 LLM plan으로 | ANSWER           |

태그 추출: `TAG_RE = /\b[A-Z]{1,5}(?:-[A-Z0-9]{1,5}){1,2}\b/i` (`:17`). 문장에 태그 없으면 **현재 뷰어 선택 태그**(`viewerContext.currentTag`), 그것도 없으면 기본 `GV-101A`.

## 4. 백엔드 분류 — `rag_server.py`

프런트가 백엔드로 넘긴 질문은 두 경로로 분류됩니다.

### 4-1. `make_plan()` — 액션 JSON 생성 (`:156`)

* "이동/가줘/위치/보여" 등이 있으면 한글 제거 후 남은 토큰을 태그로 보고 `JUMP_TO` **빠른 처리**.
* 그 외에는 `PLAN_PROMPT`(`:107`)로 LLM(qwen3)에게 action JSON을 직접 생성시킴.
* `ALLOWED_ACTIONS`(`:100`) 밖이면 폐기(환각 방지). 태그 없고 선택 태그도 "없음"이면 임의 태그 금지.

### 4-2. `resolve_intent()` — 키워드+LLM 하이브리드 (`:338`)

```
1) classify_question()  키워드 빠른길
      └ category != manual  → 즉시 확정 (confidence 1.0)
      └ manual + 진짜 매뉴얼신호 → 확정
2) 키워드 미스(=애매한 manual) → classify_intent_llm()  LLM 재분류
      └ confidence ≥ 0.6 → 채택
      └ < 0.6           → low_conf(되묻기 신호)
3) LLM도 실패 → manual/rag 폴백
```

### 4-3. `classify_question()` 키워드 표 (`:216`)

검사 순서 = 우선순위. 위 카테고리가 먼저 가져갑니다.

| 순서 | category        | 트리거 키워드                                                                                              |
| ---- | --------------- | ---------------------------------------------------------------------------------------------------------- |
| 1    | `spatial`     | 작업공간, 공간충분, 간섭, 사다리, 발판, 고소작업, 추락, 개구부, 2m이상                                     |
| 2    | `workflow`    | **단계, 체크리스트, 다음작업, 준비사항, 점검사항, 누락, 미완료, 완료안**                             |
| 3    | `cycle`       | 주기, 예정일, 다음정비, 부품 / (교체+해야·할까·검토·필요)                                               |
| 4    | `maintenance` | 이력, 분해정비, 가스켓, 누설, 고장유형, 반복, 점검결과, 정상이, 미조치, 오픈포인트, open point             |
| 5    | `manual`      | 절차, 방법, 어떻게, 교체기준, 보수기준, 점검기준, 토크, 예비품, 특별점검, 매뉴얼, 지침, 조치기준, 이상징후 |
| -    | (기본)          | 위에 안 걸리면`manual/rag`                                                                               |

## 5. ⚠️ 알려진 오분류 사례 — "분해 후 점검 체크리스트"

**증상:** "글로브밸브 분해 후 점검 체크리스트 알려줘" → `"…에 대한 진행 중 작업오더가 없습니다. (mock)"`

**원인 (임베딩 아님, 라우팅 문제):**

1. 질문에 **"체크리스트"** 포함 → `classify_question` 2번 규칙(`:228`) / `isStageQuery`(`:270`)이 **`workflow`(작업오더)** 로 분류.
2. 매뉴얼 벡터검색은 **호출조차 안 됨**.
3. 현재 선택 태그(`25-HP1-AA2-1014-105(P)`)로 작업오더 mock DB 조회 → 레코드 없음.
4. `buildStageAnswer`(`:275`)의 "(mock) 작업오더 없음" 메시지 출력.

**충돌 이유:** "체크리스트"가 두 곳에 동시에 존재

* 매뉴얼: `17.4 분해 후 점검 **체크리스트**` (정비 절차)
* mock 데모: 작업오더의 현재 단계 **체크리스트** (WO 진행상황)
  → 분류기가 **WO를 우선**하도록 짜여 있어 매뉴얼 질문이 WO로 샘.

**참고: 인덱스는 정상.** `data/manual_chunks.json` 전체 160청크 중 Globe 분해/점검 관련 12청크가 `valveType=globe`로 정상 인덱싱됨. 검색만 탔으면 정답이 나왔을 내용.

### 개선안

1. **규칙 세분화** — "분해·정비·점검"과 함께 쓰인 "체크리스트"는 `manual`로, 맥락 없는 단독 "체크리스트/단계"만 `workflow`로. (`classify_question` + `isStageQuery` 양쪽)
2. **WO 미스 폴백** — `WorkflowDB`에 작업오더 없으면 "(mock) 없음"으로 끝내지 말고 매뉴얼 RAG로 자동 재검색.
3. **매뉴얼 신호 보강** — `MANUAL_SIGNALS` / `isManualQuery`에 "점검 항목·점검 리스트·분해 후 점검" 추가.
