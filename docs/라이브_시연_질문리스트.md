# 라이브 시연 질문 리스트 (A안: Ollama·RAG·app.db 실구동)

> 실제 챗봇으로 시연할 때 **입력할 질문**과 **예상 라우팅/출처**를 정리한 운영용 문서입니다.
> 답변 전문은 `docs/시연_시뮬레이션_스크립트.md`를 참고(= 폴백 대본).
> **핵심 원칙: 시드된 태그(GV-101A 등) + 인덱싱된 매뉴얼(017/018) 범위 안에서만 질문.**

---

## 0. 시연 전 체크 (3단계)

1. **시드 검증** — ✅ 완료. `app.db`의 GV-101A maintenance/spatial/workflow가 대본 숫자와 일치(확인 끝).
2. **서버 기동**
   ```powershell
   ollama list                       # qwen3.5:9b 로드 확인
   python backend/rag_server.py      # "준비 완료: 100청크" + http://localhost:8090
   ```
   그 후 브라우저로 `index.html` 오픈.
3. **컨텍스트 고정** — DB 질문(아래 Tier 1) 전에는 **다른 태그로 JUMP 하지 말 것.**
   - 아무것도 선택 안 한 상태면 `classifier.js`가 자동으로 **GV-101A**를 기본 대상으로 잡음.
   - JUMP_TO로 다른 태그(TG-BRG-002 등)로 이동하면 `currentTag`가 바뀌어 "이 밸브" 질문이 그 태그로 가버림 → **DB에 없으면 "등록되어 있지 않습니다"** 출력.
   - 가장 안전: **DB 질문(Tier 1)을 먼저 끝내고, 뷰어 조작(Tier 3)은 나중에.**

---

## Tier 1 — 결정적 일치 (DB 규칙 기반 · 대본과 100% 동일)

> Ollama 문장 생성을 거치지 않는 **규칙 기반 답변**이라 매번 똑같이 나옴. 발표의 안전한 메인.
> 모두 GV-101A 대상(태그 미입력 시 기본값). 더 확실히 하려면 문장에 `GV-101A`를 직접 넣어도 됨.

### 정비 이력 (cat 3)
- 이 밸브의 최근 정비 이력 보여줘
- 이 밸브는 마지막으로 언제 분해 정비했어?
- 이 밸브 보닛 가스켓 교체 이력 있어?
- 이 밸브에서 과거에 누설 이력이 있었어?
- 이 밸브에서 반복적으로 발생한 고장 유형이 뭐야?
- 이 밸브의 최근 점검 결과는 정상이야?
- 이 밸브에 등록된 미조치 사항이나 Open Point 있어?

### 정비 주기 (cat 4)
- 이 밸브의 정비 주기 지났어?  *(오늘 2026-06-23 기준 동적 계산 → 초과)*
- 이 밸브는 다음 정비 예정일이 언제야?
- 정비 주기 기준으로 우선 점검해야 할 부품 알려줘
- 최근 누설 이력을 고려하면 그랜드패킹을 교체해야 해?

### 작업 조건 (cat 5 · Walkinside 공간데이터)
- 이 Globe Valve 주변 작업 공간 충분해?
- 이 밸브 정비할 때 작업발판이 필요해?
- 이 밸브는 2m 이상 고소작업에 해당돼?
- 이 밸브 주변에 추락 위험이나 개구부가 있어?

### 작업 단계 (cat 6 · 작업오더 WO)
- 지금 이 밸브 정비는 어느 단계까지 완료됐어?
- 다음 작업 단계 알려줘
- 현재 단계에서 확인해야 할 체크리스트 보여줘
- 분해 전 준비사항 중 완료 안 된 항목 있어?
- 조립 전 점검사항 중 누락된 항목 있어?

## Tier 2 — 근거 고정·문장 생성 (매뉴얼 RAG · Ollama)

> 출처/근거는 매뉴얼로 고정되지만 **문장 표현은 Qwen3가 매번 생성**(미세 변동 정상).
> ⚠️ **반드시 트리거 단어 포함**: `절차 / 방법 / 어떻게 / 기준 / 매뉴얼 / 지침`.
> 이 단어가 있으면 `isManualQuery`가 **가장 먼저** RAG로 보내, 아래 "오답 유발 단어"가 섞여도 안전.

- 게이트 밸브 점검 기준과 특징을 매뉴얼에서 알려줘   *(gate 필터)*
- 글로브 밸브와 게이트 밸브 정비 절차에서 다른 점 알려줘
- 밸브 정비 착수 전 안전 절차 알려줘
- 꼬리표(Red Tag) 부착 기기 조작 지침 알려줘
- 밀폐공간 작업 산소농도 기준이 매뉴얼에 어떻게 나와?   *(→ 18%)*
- 고소작업 기준 높이가 매뉴얼에 어떻게 나와?   *(→ 2m. "추락"은 빼기)*
- 절연전선·플라스틱 부품 세척제 사용 지침 알려줘   *(→ TCE 금지)*
- 인적실수 예방 자기진단 절차 알려줘   *(→ Stop-Think-Act-Review. "4단계"는 빼기)*
- 밸브 분해 전 준비 절차 알려줘   *(→ Match Mark)*
- 자력밀봉식 보닛 분해 방법 알려줘
- 사용한 가스켓 재사용 지침이 어떻게 돼?   *("지침" 덕분에 RAG로 감)*
- 스템 점검 기준 알려줘
- 디스크와 시트 접촉상태 불량 시 조치 방법 알려줘   *(→ 래핑/육성용접/PT)*
- 그랜드패킹 이음부 배열 각도 절차 알려줘   *(→ 180/120/90°)*
- 그랜드너트 조임 절차 알려줘   *(→ 3회)*
- 정비 완료 후 성능시험 절차 알려줘

## Tier 3 — 뷰어 조작 (액션은 실행되나 텍스트는 일반 메시지)

> 회전/숨김/필터 등 **동작은 실제로 일어남**(mockViewer). 단, 답변 텍스트는 대본의 풍부한 문구
> ("3건 찾았습니다, TG-LOP-001…")가 아니라 **일반 메시지**로 나옴. 시각 효과 위주로 시연.

- 이 장비 뒷면 보여줘   *(ROTATE 180°)*
- 밸브가 안 보이게 꺼줘 → 밸브 다시 보여줘   *(HIDE/SHOW)*
- 펌프만 보여줘   *(FILTER_BY_TYPE)*
- TG-BRG-002 위치로 안내해줘   *(JUMP_TO · KNOWN_TAGS에 있음 ✅)*
- 비상 탈출 경로 보여줘   *(SHOW_PATH)*

❌ **라이브에서 피할 것 (DB/뷰어에 없음 → 빈 결과·오류)**
- "터빈 윤활유 펌프 찾아줘" 류에서 나오는 `TG-LOP-001`, `GV-102B`, `HX-301`, `P-201` 태그를 직접 조회/이동
- 시드 안 된 태그로 "이 밸브 이력" 질문

## 라우팅 주의 메모 (왜 문구가 중요한가)

`classifier.js` 처리 순서는 **① 매뉴얼 RAG(isManualQuery) → ② 규칙(DB 핸들러) → ③ LLM plan** 입니다.

| 의도 | 위험한 단어 | 안전한 문구 |
|---|---|---|
| 매뉴얼인데 DB로 샘 | 가스켓·이력·누설(→정비이력 DB) / 추락·발판(→공간 DB) / 단계(→작업단계 DB) | 앞에 **절차/방법/지침/기준/매뉴얼** 붙이기 |
| DB 질문인데 안 걸림 | 트리거 누락 | Tier 1 문구 그대로 사용 |

> 즉, **매뉴얼 질문엔 항상 "절차/방법/지침/기준/매뉴얼/어떻게"를 넣는다** 이 한 줄만 지키면 라우팅이 안정적입니다.

## 리스크 & 폴백

- Ollama 응답은 질문당 수 초 지연 → 발표 흐름에서 "로컬 LLM이 생성 중"이라고 멘트.
- 매뉴얼(Tier 2) 문장이 대본과 달라도 **출처·근거가 같으면 정상**임을 미리 깔아두기.
- 라이브가 막히면 즉시 `docs/시연_시뮬레이션_스크립트.md`(B 대본)로 전환 — 같은 질문/답을 그대로 읽기.
