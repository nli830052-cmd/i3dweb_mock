## 2. 슬라이드별 핵심 내용 및 스크립트 가이드

### [Slide 1] 표지: RAG & 3D Viewer 연동 스마트 설비 유지보수 AI 어시스턴트
* **기술 스택 키워드**: `Local RAG`, `BAAI/bge-m3`, `Numpy Flat Vector Index`, `qwen3.5:9b (Ollama)`, `Vanilla JS Action Dispatcher`
* **핵심 메시지**: "유지보수 지침서 RAG와 3D CAD 모델 제어를 결합한 온프레미스 AI 어시스턴트 프로토타입 구현기를 공유합니다."

---

### [Slide 2] 아키텍처 설계: 느슨한 결합(Loose Coupling)을 통한 Viewer 제어
* **아키텍처 포인트**:
  * AI가 직접 뷰어 API를 실행하지 않고, 자연어 해석 결과물로 **정형화된 JSON(Action Plan)**을 리턴합니다.
  * 프론트엔드의 중계 레이어([actionExecutor.js](file:///c:/lyn/i3dweb_mock/src/core/actionExecutor.js))가 JSON을 파싱하여 Viewer SDK를 디스패치합니다.
  * **개발자 타겟 어필**: "이 설계 덕분에 뷰어 API 스펙이 변경되거나 AI 모델을 OpenAI, Claude 등으로 교체하더라도 상호 간에 영향 없이 독립적인 개발 및 고도화가 가능합니다."

---

### [Slide 3] 데이터 엔지니어링: 계층형 청킹 (Hierarchical Chunking)
* **구현 방식 ([ingest_manuals.py](file:///c:/lyn/i3dweb_mock/scripts/ingest_manuals.py))**:
  * 단순 글자 수 슬라이싱은 정비 순서나 필수 수치의 맥락을 훼손합니다.
  * PDF 지침서에서 `8.1.1 분해 전 준비`와 같이 문서 내 번호 체계(`\d+(\.\d+)*`)를 파싱하여 **의미론적 섹션 단위**로 1차 분리합니다.
  * 200자 미만의 너무 작은 섹션은 부모가 같은 인접 형제 섹션과 자동 병합하고, 900자 이상의 초과 청크는 80자의 Overlap을 주어 균등하게 분할(Windowing)합니다.
  * 각 청크마다 `section_path` (예: `Gate Valve 정비 > 8.0 정비절차 > 8.1 분해`)를 동적으로 만들어 텍스트 앞에 빵부스러기(Breadcrumb)로 부착하여 임베딩 퀄리티를 향상했습니다.

---

### [Slide 4] 검색 최적화: NumPy Flat Vector Indexing
* **임베딩 및 인덱싱 ([embed_chunks.py](file:///c:/lyn/i3dweb_mock/scripts/embed_chunks.py), [search_manuals.py](file:///c:/lyn/i3dweb_mock/scripts/search_manuals.py))**:
  * 로컬 임베딩 모델로 `BAAI/bge-m3`을 활용하여 청크를 1024차원 벡터로 변환합니다. 임베딩 시 L2 정규화를 거칩니다.
  * 별도의 무거운 외부 Vector DB 설치를 배제하고, `numpy.save()`를 사용하여 정규화 벡터들을 단일 `.npy` 파일로 저장하고 매칭 메타데이터는 `.json`에 보관합니다.
  * 검색 시 쿼리 벡터와 인덱스 행렬 곱(`vecs @ q`)을 통해 코사인 유사도를 초고속 연산합니다.
  * `min_score=0.30` 필터링 및 현재 선택된 설비 태그의 `valve_type` (gate/globe) 사전 필터링으로 무관한 검색 결과를 배제합니다.

### [Slide 5] 의도 추론 및 Grounding 프롬프트 제어
* **LLM 제어 ([backend/rag_server.py](file:///c:/lyn/i3dweb_mock/backend/rag_server.py))**:
  * Ollama를 통해 로컬에 서빙된 `qwen3.5:9b` 모델을 행동 계획기(Action Planner)와 답변 생성기(Answer Generator)로 이중 활용합니다.
  * **행동 계획**: 사용자 질의 문맥과 대화 이력(Session History)을 바탕으로 의도를 판별하여 `responseType`과 JSON Action 배열을 자동 매핑합니다.
  * **환각 제어**: RAG 답변 시 프롬프트에 제공된 `[매뉴얼 발췌]` 데이터 외의 정보는 절대 답변하지 못하도록 프롬프트 레벨에서 강력한 제약을 걸었습니다. ("지침서에서 확인되지 않습니다"로 폴백 처리)

## 3. 라이브 데모 시나리오 실행 가이드

라이브 데모는 Ollama와 로컬 RAG 서버가 연동되어 동작하는 흐름을 보여주며, 브라우저의 **"API 흐름 패널"**을 띄워놓고 AI 백엔드와 Viewer SDK의 통신 과정을 실시간으로 모니터링시키는 형태로 진행합니다.

### 3-1. 데모 사전 준비 (시작 전 부스 설정)
1. **Ollama 구동**:
   ```powershell
   # Ollama가 로컬에서 러닝 중인지 확인
   ollama list
   # qwen3.5:9b (또는 설정된 모델) 로드 확인
   ```
2. **RAG 백엔드 서버 시작**:
   ```powershell
   # 프로젝트 루트(c:\lyn\i3dweb_mock)에서 구동
   python backend/rag_server.py
   ```
   * *기대 로그*: `준비 완료: xx청크, 모델=BAAI/bge-m3` 및 `RAG API: http://localhost:8090` 포트 바인딩 완료 메시지 확인.
3. **웹 테스트 페이지 오픈**:
   * 브라우저에서 `index.html` 파일을 엽니다.

---

### 3-2. 실시간 라이브 시연 시나리오 (4분)

#### **[시나리오 1] RAG 기반 정비 지침 검색 (순수 ANSWER)**
* **입력**: `"글로브 밸브 그랜드패킹 교체 절차를 알려줘"`
* **화면 모니터링 포인트**:
  * 챗봇 응답 영역에 매뉴얼 절차 순서가 출력되는 동시에 밑에 **출처 도큐먼트(예: 절차-표준-018 Globe Valve 정비, 12페이지)**와 유사도 매칭 스코어가 표기됩니다.
  * API 흐름 패널에서 `[AI팀/HTTP]`로 검색 및 답변 생성이 로컬 RAG 백엔드에서 원활히 이루어진 것을 시각적으로 공유합니다.

#### **[시나리오 2] 3D Viewer 연동 제어 (순수 ACTION)**
* **입력**: `"TG-BRG-002로 이동하고 시점 뒤로 돌려줘"`
* **화면 모니터링 포인트**:
  * AI가 `JUMP_TO` (targetValue: TG-BRG-002)와 `ROTATE_VIEW` (direction: back) 두 개의 액션을 동시에 리턴한 것을 확인합니다.
  * Mock Viewer의 좌표계가 업데이트되면서 우측 상단 뷰어 영역에 `State: MOVED | Direction: BACK`으로 실시간 변경되는 액션 실행 로그를 확인시킵니다.

#### **[시나리오 3] 복합 지시어 처리 (ANSWER_WITH_ACTION)**
* **입력**: `"TG-VLV-205로 이동하고 보닛 분해 절차 요약해줘"`
* **화면 모니터링 포인트**:
  * `responseType`이 `ANSWER_WITH_ACTION`으로 파싱되어, 3D 뷰어 화면 이동(`JUMP_TO`)과 본문 RAG 검색이 동시 작동하는 하이브리드 연동을 보여줍니다.

#### **[시나리오 4] 비정상 흐름 및 예외 제어 (Error Handling)**
* **입력**: `"TG-INVALID-999 설비로 가줘"`
* **화면 모니터링 포인트**:
  * RAG API는 정상적으로 200 OK를 응답하지만, 뷰어 SDK 단에서 해당 가상의 설비를 찾지 못해 `TAG_NOT_FOUND` 예외 콜백을 반환하고 Mock Viewer가 빨간색 경고 상태로 쉐이킹되는 예외 처리 견고함을 검증합니다.

**진행 규칙 2가지**
1. **컨텍스트 고정**: DB 질문(A~D)을 **먼저** 끝내고, 뷰어 이동(G)은 **나중에**. 다른 태그로 JUMP하면 "이 밸브" 기준 태그(GV-101A)가 바뀌어 빈 결과가 날 수 있음.
